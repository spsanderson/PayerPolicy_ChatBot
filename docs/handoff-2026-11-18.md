## What was implemented

A guarded, opt-in corrected derived-text view was added for spacing that was
proven to be inserted by pypdf's `TJ` position inference.

Changed files in commit `945d041`:

- `payer_policy/text_extraction.py`
- `tests/test_text_extraction.py`
- `docs/text-extraction.md`
- `docs/source-reviews/pa-text-quality-pilot.md`

The implementation:

- preserves original PDF bytes and raw parser output;
- requires retrieval ID, source SHA-256, parser version, page number, exact raw
  span, content-stream operation index, and TJ item index;
- rejects stale hashes, mismatched raw text, repeated or overlapping spans,
  wrong TJ operations, wrong adjustments, literal spaces, and unrelated text;
- performs an isolated counterfactual extraction;
- supports indirect and array-based PDF content streams;
- never globally replaces every `Y ` and does not alter default pypdf behavior.

The two confirmed amendments-page-1 cases were:

- raw offset `287`, operation `50`, TJ item `1`;
- raw offset `418`, operation `1425`, TJ item `1`;
- both had numeric adjustment `+126`.
